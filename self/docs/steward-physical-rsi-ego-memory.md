# Steward、Physical RSI 与 Ego 记忆梳理

整理日期：2026-11-06。本文基于本次讨论与本地代码阅读，区分设计目标和当前实现，不代表实机验收结论。

## 1. Steward 与 Physical RSI 的理念是否类似

核心理念接近。Steward 已具备世界认知、行动预测、失败反思和能力积累等结构；完整的 Physical RSI 还要求世界模型与行动能力通过经验共同改进。

参考文章：[Building Physical RSI Beyond the Known World](https://mirros.ai/research/building-physical-rsi-beyond-the-known-world)。文章强调：遭遇意外后，判断是世界模型无法解释现象，还是行动能力不足；随后修正模型、寻找解法、验证结果，并将经验积累为可复用知识与技能。

| 核心思路 | Steward 对应机制 |
|---|---|
| 世界认知不完整且可能出错 | Ego-State（ES）来自机器人自身感知，带不确定度，与世界真值 GT 隔离 |
| 行动前预测后果 | Ego-Simulation（ESim）基于 ES 预测风险 |
| 失败后重新理解问题 | Ego Harness（EH）反思感知、物体状态、动作与任务理解，提出假设并寻找证据 |
| 积累可复用能力 | 用 `run_code` 组合机器人工具，将程序保存为 capability |
| 系统性检验意外情况 | World Harness（WH）构建场景、编排扰动；Observer 对比 ES 与 GT |

### 关键差别

更新世界状态与改进世界模型是两类工作。发现杯子移动后更新位置属于状态估计；发现原来的摩擦、接触或几何假设无法解释失败，进而修正预测规律，才更接近文章所说的模型演化。设计包含预测与实际对比来校正物理参数的方向，但当前 ESim 主要执行几何与概率风险检查，完整物理推演仍是后续目标。

WH 不能直接等同于文章里的 world agent。WH 能读取 GT，负责场景构建与实验编排；机器人自身对世界的认识主要由 ES 和 ESim 承载。要形成文章描述的闭环，还需要将机器人遭遇的失败自动转成可复现、可生成变体的实验场景。

能力库提供持久积累机制，但当前成功统计包含“程序无错误结束”，不能单独保证物理任务达成。更完整的持续学习还需要目标验证、跨场景回归，以及失败后修订技能或模型。

进一步演进的闭环是：失败 → 判断世界模型缺口或技能缺口 → 复现场景 → 修正 → 跨场景验证 → 持久积累。

## 2. Steward 如何对应真实世界

Ego 系统可以理解为机器人 Agent 在真实世界中的部署态。Steward 整体还包括支持它的仿真、实验与评估设施。

| 组件 | 仿真中 | 真实世界中 |
|---|---|---|
| 外部世界 | WSim 模拟的房间、物体与机器人 | 实际环境与机器人本体 |
| 硬件抽象层 HAL | 读取模拟传感器并执行仿真动作 | 连接真实相机、编码器、控制器和执行器 |
| ES | 从仿真传感器建立局部世界认知 | 从真实传感器建立局部世界认知 |
| ESim | 根据 ES 预测行动后果 | 继续根据 ES 预测行动后果 |
| EH | 理解任务、编排技能、处理失败 | 继续承担相同职责 |
| WH / Observer | 构建场景、注入扰动、读取 GT 评估 | 用于实验编排和外部测量；完整 GT 通常不可得 |

迁移到实机时，外部 WSim 被现实替代，内部 ESim 仍然存在。机器人仍需要在执行前判断能否抓取、是否会碰撞、放置是否稳定。

### 部署层次

1. Ego Harness：理解任务、拆解目标、调用工具、反思失败、复用能力。
2. Ego Runtime：持续感知、维护 ES、规划运动、预测风险、执行技能和安全监督。
3. 硬件适配与控制：接入具体机器人的传感器、控制器和执行器。

这些组件可以分布在机载电脑与远端服务器上。实时控制和安全机制应在本地运行，语言模型可以远程调用。

“替换 HAL，上层保持一致”是架构目标，仍需实机验证。标定误差、通信延迟、抓取打滑、接触偏差和硬件故障可能要求调整技能实现、物理参数与安全机制；本次阅读的项目进度中，实体机器人阶段仍属规划。

未来可将部署系统与实验设施连接起来：实机失败回传 → 仿真复现 → 改进技能或模型 → 验证后部署。

## 3. Ego 当前有哪些记忆

Ego 已有几种分散的记忆机制，尚不能等同于统一的长期记忆系统。

| 记忆类型 | 内容 | 保留范围 |
|---|---|---|
| 世界状态记忆 ES | 物体、位置、类别、不确定度、支撑与包含关系等 | Ego Runtime 运行期间持续维护；不能据此推断重启后自动恢复 |
| 任务与反思记忆 | 当前指令、失败步骤、反思内容 | 当前任务与会话；反思历史有长度限制 |
| 程序工作记忆 | `run_code` 中的变量和辅助函数 | 同一 Harness 进程内 |
| 长期能力记忆 | 技能程序、任务组合方法、参数说明、版本与使用结果 | 写入磁盘，跨会话、跨场景保留 |

### 世界状态记忆：世界现在是什么样

ES 持续融合观测，不要求物体始终出现在相机画面中。例如，关着的抽屉内已知物体不会仅因暂时不可见而立即被忘记；机器人移动容器时，会相应更新其中物体的位置。这属于运行期间维护的世界认知。

### 长期能力记忆：某类事情怎么做

Agent 可以把程序保存为可复用的 `skill`，也可以保存组合多个技能的 `recipe`。后续任务通过 `capability_list` 和 `capability_get` 找回代码，再在 `run_code` 中执行。

能力以 JSON 文件保存在机器人自己的 `DSH_HOME/steward-capabilities/`。代码变化会形成新版本；运行记录可使能力进入 `verified` 或 `deprecated` 状态；删除能力会将记录移至 `forgotten/`，保留原因。这里的 `verified` 是当前实现的运行统计状态，不等于已完成实机验证或跨场景泛化验证。

### 尚未形成完整机制的记忆

会话日志留存与长期记忆检索是不同能力。从本次阅读的实现看，还没有形成完整机制，自动提炼、保存并按需召回生活经历、用户偏好或物理经验，例如“昨天杯子被放在哪里”“主人偏好什么摆放方式”“某种材质经常打滑”。

因此，目前可以确认 Ego 有当前世界的记忆、当前任务的记忆，以及可持久积累的做事方法。跨天经历、用户偏好和物理规律经验的长期记忆仍有待补齐。
