# Steward 感知模型与物体定位说明

这份说明回答：向 steward-bot 下达“把桌上的杯子拿到柜子上”时，它怎样识别目标、怎样得到位置，以及各感知模式使用了哪些仿真信息。范围是普通机器人 Ego 对话路径；World Harness 编辑场景和显式真值调试另行说明。代码与本机模式检查日期为 2026 年 11 月 6 日。

## 1. 先区分三件事

**识别物体**是判断哪些区域属于一个物体、它可能是什么；**定位物体**是估计物体相对于相机或机器人地图的位置；**理解任务**是从已知对象中选出操作员指的杯子和柜子，再决定动作。这三件事由不同部分完成，不能把语言模型选中目标理解为语言模型直接从图片计算了精确坐标。

World State 是模拟器维护的真实场景，Ego-State 是机器人根据观测积累的估计。普通机器人模型通过 Ego 工具读取后者。控制台能为操作员显示真实位置，不代表这些位置直接交给了机器人。

判断是否使用真值，也要区分“直接拿物体位置”“仿真提供物体分割”“仿真模拟深度和里程计”。四种模式对这三类信息的使用不同。

## 2. 四种模式总览

| 模式 | 物体区域或检测从哪里来 | 类别从哪里来 | 位置从哪里来 | SAM 是否参与 |
|---|---|---|---|---|
| `phase0` | 仿真根据可见性生成检测及包围盒 | 仿真类别，可能加入类别混淆 | 仿真真实几何生成带噪声的相机相对位姿，机器人再转换和融合 | 否 |
| `phase0-misnamed` | 与 phase0 相同 | 在理想检测上按配置替换部分名称 | 与 phase0 相同 | 否 |
| `phase1` | 仿真提供匿名实例掩码 | 机器人根据可见几何、颜色等形状先验分类 | 机器人根据模拟深度、相机参数和自身位姿计算 | 否 |
| `phase1-sam` | SAM 根据 RGB 生成实例掩码 | SAM 类别分数与机器人形状先验融合 | 与 phase1 一样根据深度恢复几何，再转换和融合 | 是 |

四种模式都在仿真环境中运行。`phase0` 两种变体直接使用真值生成的检测，`phase1` 使用仿真分割辅助，`phase1-sam` 才让真实视觉模型承担分割与语义识别。后两种都使用模拟深度和本体传感器，并非仅凭 RGB 完成全部定位。

## 3. 每种模式怎样找到杯子和柜子

### 3.1 phase0：仿真提供理想检测

模拟器遍历场景物体，用相机视野、距离和遮挡检查决定哪些目标能够被看到。对可见目标，它根据真实几何计算相机相对位姿和包围盒，再加入位置、尺寸、朝向等噪声，生成带类别、置信度、尺寸和颜色的检测。

```text
World 物体真实几何
  → 相机可见性检查
  → 带噪声的类别、包围盒和相机相对位姿
  → 机器人坐标变换与跨帧融合
  → Ego-State 中的杯子和柜子
```

机器人不需要从 RGB 图像识别杯子或柜子，也不需要从深度恢复这次检测的三维位置。这是“仿真直接生成检测结果”的模式，不能当成视觉识别能力的验证。它仍不是全知：视野外或被遮挡的物体不会因为存在于 World 就全部出现在一次检测中；检测也有噪声及透明物体漏检、类别混淆等模拟误差。

例如桌上杯子可见时，检测会提供类似 cup 和相机相对位姿的信息；机器人把它变换到 map 坐标系并积累。柜子同理。最后任务模型查询的仍是融合后的 Ego-State，而不是直接读取完整 World 实体表。

### 3.2 phase0-misnamed：位置检测不变，名称故意混淆

这个模式沿用 phase0 的可见性、带噪声检测与定位流程，只对配置中的类别改名。默认 `misnames.toml` 把 box 报成 picture，把 table 报成 dinner table；它没有默认把杯子和柜子都改名。

```text
phase0 理想检测
  → 按 misnames.toml 替换配置中的类别名称
  → 相同的坐标变换与状态融合
  → 名称可能与操作员叫法不一致的 Ego-State
```

它主要检验任务模型能否处理“东西在，但名字不同”，包括候选检索、观察确认、标注和失败反思。坐标仍来自真值生成的带噪声检测，不是视觉模型估计。找不到“盒子”时，问题可能只是它被报成 picture，而不是物体没有被检测到。

### 3.3 phase1：仿真给物体区域，机器人恢复几何并分类

模拟器提供 RGB、带噪声深度和匿名实例掩码。掩码指出哪些像素属于同一实例，但不提供类别或 World 实体身份，编号每帧打乱。掩码来自模拟器几何分割，因此属于仿真辅助。

```text
RGB + 模拟深度 + 仿真匿名掩码
  → 取出各区域的有效深度像素
  → 恢复三维点并变换到 map 坐标系
  → 测量几何、按形状先验分类、推断支撑关系
  → 跟踪并融合成 Ego-State
```

例如杯子区域已由仿真分开，但机器人仍要根据测量到的尺寸、形状、颜色等判断它像杯子还是碗；柜子也可能因只看见局部而分类错误。物体的实际位置由掩码内的深度计算，没有直接拿杯子或柜子的绝对真值坐标。

这个模式检验三维感知和估计链路，但没有检验真实分割网络能否从图像正确分开物体。它不调用 SAM。机器人自己的类别和物体轨迹仍可能与真实场景不同。

### 3.4 phase1-sam：SAM 找区域和类别，机器人恢复三维位置

模拟器向该感知路径提供 RGB 和带噪声深度，不提供仿真实例掩码。Ego Runtime 在关键帧自动将 RGB 和配置的类别提示词交给远程 SAM 3.1，获取区域和类别分数。

```text
RGB + 模拟深度
  → SAM 根据 RGB 和提示词输出掩码、类别分数
  → 对桌面等区域裁剪放大，必要时再次分割找小物体
  → 用区域内的深度恢复三维几何并变换坐标
  → 融合 SAM 语义、形状先验和多次观测
  → Ego-State 中的杯子和柜子估计
```

提示词来自 `segmentation.toml`，包括 cup、mug、cabinet、sideboard、kitchen counter 等。后台感知按配置识别环境，再供任务模型查询；不是每收到一句任务就把整条命令交给 SAM。多个提示词命中同一个区域时，分割器按重叠合并实例并保留类别分数，估计器再与形状先验融合。因此 SAM 分数也不等于最终类别概率。

SAM 只负责区域和语义证据，不直接输出供机器人使用的三维坐标。小杯子可能漏检，柜体可能被分成几块，两个相邻物体也可能粘连。当前配置支持对桌面等支撑区域裁剪放大再识别；默认关闭的 `geometric_fill` 意味着不能假定深度聚类会自动补齐所有漏检对象。

SAM 调用按首次观测、移动、转向、静止、手臂状态及时间条件选择关键帧，不是逐渲染帧请求。相同图像和分割配置可以命中缓存。分割失败时会记录错误并告警，该帧只更新机器人自身状态，不自动退回仿真掩码或理想检测。历史物体估计可能仍在，因此查询还能返回对象不等于本帧分割成功。

## 4. 深度怎样变成具体位置

本节适用于 phase1 和 phase1-sam；区别仅在于使用仿真掩码还是 SAM 掩码。两者的深度均由 MuJoCo 渲染并加入噪声，不是 SAM 或单目深度模型从 RGB 预测的。

图像位置提供观察方向，深度提供表面距离，相机内参把二者转换成三维点。代码中相机安装坐标系为前方 +X、上方 +Z；像素 `(u,v)`、深度 `d` 和焦距 `f` 对应局部点：

```text
[d, -(u-cx)d/f, -(v-cy)d/f]
```

Steward 再结合机器人里程计、关节编码器和相机安装参数，把这些点旋转、平移到机器人 map 坐标系，估计可见几何和物体位置，并关联、融合多次观测。形状先验也可能用于推断未见部分，因此最终物体估计不只是当前可见像素点的集合。

| 信息 | 来源 |
|---|---|
| RGB | 模拟相机渲染 |
| 度量深度 | 模拟深度传感器，包含噪声及无效读数 |
| 里程计 | 仿真底盘状态加噪声后的模拟读数 |
| 关节读数 | 仿真关节编码器 |
| 相机内参和安装关系 | 机器人模型及相机配置 |
| 物体 map 坐标 | 从观测恢复几何、坐标变换和融合得到 |

例如杯子区域某个像素深度约 1.2 米，这只是一个表面点的深度，不能直接当成杯子中心距离。区域内多个有效点共同支持物体估计。Ego-State 可能返回 `(1.4, 0.6, 0.8)` 米这样的 map 坐标；此处数字仅为形式示例，不是本机实测，也不是 SAM 直接输出。

只看到部分表面、分割错误、深度缺失、形状先验不匹配和里程计误差都会影响结果。map 坐标与 World 坐标数值接近，也不能据此认定直接读了真值；仿真里程计误差本来就可能较小。

## 5. 从物体估计到“搬杯子”的完整任务

### 5.1 先找到操作员指的对象

四种模式最后都向机器人模型提供 Ego-State。模型先用 `ego_state` 查看已知物体，或用 `ego_query` 按类别、用途标签和邻近关系检索，找出桌上的杯子及目标柜子。机器人使用自己分配的 `e:` 物体标识，不直接沿用 World 实体标识。

`category` 是感知分类，`role` 是结合场景推断的用途标签。柜子局部可能被分类成 counter，仍可能依据 role 找到；杯子也可能被叫作 mug 或 bowl。模型需要结合颜色、尺寸、支撑关系和其他证据选择对象，多只杯子时不能只凭 cup 就认为目标唯一。

找不到或不确定时，模型需要 `ego_explore` 环顾、换角度或靠近观察，再等待状态更新。查询不会凭任务描述补出未知物体位置，已知记录也可能来自此前观测而非此刻可见。

### 5.2 “把桌上的杯子拿过来”

```text
查询已知杯子与桌子
  → 结合支撑关系等证据选择桌上的目标
  → 找不到则探索或靠近观察
  → 明确交付位置
  → ego_predict 检查动作并生成收据
  → skill_run 执行
  → 查询状态检查结果
```

四种模式的任务流程相同，差别是第一步的物体记录由第 3 节中哪条感知路径产生。“拿过来”如果没有可执行的交付位置，需要结合任务语境确定，必要时询问操作员；识别杯子不等于确定了放置目标。

### 5.3 “把桌上的杯子拿到柜子上”

模型需要同时找到杯子与柜子。杯子估计用于接近、抓取，柜子的几何与支撑面估计用于选择放置区域。柜子中心不是放置点，还要检查高度、空位、物体尺寸、可达性和碰撞风险。

普通机器人任务提示要求每个动作先 `ego_predict`，获得收据并检查风险后再 `skill_run`，执行后通过 Ego 状态自查。预测依据机器人自己的状态估计；实际动作由模拟物理世界执行，所以估计看似可行仍可能抓空或碰撞。工具执行成功也不意味着整个任务已经满足，需要检查最终状态。

“拿到柜子”还可能指放进柜内或移到旁边，具体动作取决于任务语境。本例明确为柜子上表面，不能据此假定所有柜子都有可用容纳空间。

## 6. 失败后的 Ego reflection

标准 Ego bundle 的反思插件监听工具执行结果：报错、预测不可行、技能失败或物体查询为空时，可以自动收集证据并追加反思提示；工具未失败但任务没有进展时，模型也可以主动调用 `reflect`。

Python 侧按失败消息规则分类原因，从 Ego-State 提取相关物体、已丢失目标和必要的候选对象。TypeScript 插件把证据、原始指令、失败历史与固定反思问题交给当前模型，要求检查目标、现象、可能原因、验证方法和计划。它不启动另一个反思模型，也不自动执行补救动作。

| 失败现象 | 反思提供的信息与用途 |
|---|---|
| 找不到杯子 | 可以列疑似杯子或命名存疑对象，帮助模型决定观察、确认或标注 |
| 导航被柜子挡住 | 保留阻挡原因和相关柜子，不提供无关候选对象 |
| 放置空间不足 | 提示检查或处理空间，不把问题当成重新找杯子 |

候选筛选使用原因白名单，也包含未归类失败等类别，并非只有已经确定命名错误才返回候选。自动反思每条操作员指令默认最多四次，类似失败去重；程序内部已经反思时外层不重复触发。主动调用不受自动次数上限拒绝，但计入反思次数和历史。反思依据各模式产生的 Ego-State，不能消除该模式的观测限制，也不能补出真实未知位置。

## 7. 其他已接入模型与常规定位的关系

| 模型或服务 | 用途 | 是否进入上述常规物体定位路径 |
|---|---|---|
| SAM 3.1 | RGB 物体分割与语义证据 | 仅 phase1-sam 自动使用 |
| NovelAnything | 根据图像及位姿生成虚拟视角 RGB 和预测深度 | 通过工具和 skill 按任务调用，结果不自动写入 Ego-State |
| rgbd_video_gen | 根据观测序列和位姿生成一个或多个虚拟视角的 RGB-D 内容 | 提供录制、准备、生成、查询、取消及下载流程，结果不自动写入 Ego-State |
| SLARM | 探索多帧场景重建、深度、点云、场景流、3D 高斯及新视角渲染 | 有服务登记和 Python 客户端，未进入当前常规感知循环 |
| SAM 3D Objects | 根据单图及可选掩码、点云补全物体三维形状 | 登记服务供离线尝试，Phase 1 不调用 |

新视角生成的例子是：“移动时录制头部相机，生成到位后从手爪位置看过去的 RGB-D。”NovelAnything 的便捷准备工具面向手爪视角；rgbd_video_gen 支持显式指定目标位置、朝向和参考坐标系。它们输出预测文件，不增加实体相机，也不会自动成为抓取或避障的真实观测。

仓库第 13.7.6 节记录的实验结论是：Phase 1 的主要瓶颈仍在语义分割，直接加入重建和深度估计服务尚未改善所记录的 ES 效果。服务已安装、已登记或健康检查通过，不等于机器人每次搬杯子都在调用它。

## 8. 如何确认当前模式

检查本机默认 World 端口的只读接口；端口应与实际启动配置一致：

```sh
curl http://127.0.0.1:7400/wca/phase
```

读取 `level` 区分四种模式。2026 年 11 月 6 日本次会话检查返回 `phase1`，这是当时本机实例的状态，不代表其他实例或后续运行。本文整理没有修改运行模式。

命令行显式指定的阶段优先于场景声明，未指定时使用场景阶段或启动回退阶段。控制台可在运行时切换，机器人检查下一次传感器帧后跟随感知模式变化；检测与 RGB-D 路径切换时会重新建立物体估计。因此应以运行接口为准，不能只从模型安装情况推断。

World Harness 可以查询、编辑真实场景；操作员控制台也可显示 World 真值。它们与普通机器人 Ego 查询用途不同。Cobot 命令另有显式 `--ground-truth` 调试开关，不能把该路径等同于 steward-bot 普通对话。即使使用 phase1-sam，仍不能把模拟 RGB-D 与模拟本体传感器等同于实机上全部由图像估计的系统。
