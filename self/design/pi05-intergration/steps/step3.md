# Step 3：接入 Panda、夹爪和 OSC 控制器

2026-11-10（北京时间）。**状态：五个初态的 WSim 固定动作与控制权专项验收通过。** 对应[实施计划第 3 步](../pi05-integration-plan.md#3-放入配套机器人)。采用 [Step 2 已验证的 WSim 与准备态 MJCF 路线](step2-results/README.md)，控制参考为 [Step 1 原始 LIBERO 基线](step1-results/README.md)。

实测结果、轨迹、录像与复现命令见 [Step 3 阶段实测](step3-results/README.md)。

## 1. 交付范围

在 Steward 中加载带 Panda 的字母汤罐场景，按原始初态复位。通过机器人端口提交固定测试动作，观察单轴末端位移、转动与双指开合，并用固定 LIBERO 版本量化控制响应差异。验证停止、失联和重置后的动作失效。Step 4 验证实际抓取与放置，Step 5 验证策略观测，Step 6 接入模型推理。本步的轨迹对照使用固定动作，不调用 π0.5。

## 2. 本体、资产与 Scenario

1. 在固定 LIBERO checkout 导出含 `OnTheGroundPanda` 的组合 MJCF。复用 Step 2 的资源校验、场景资产与独立视觉和碰撞体。保留源模型有效质量、质心和主惯量，避免新版本 MuJoCo 按 mesh 重新推导。对照编译模型检查基座、关节轴和限位、执行器类型、传动、限幅、碰撞过滤及站点。
2. Panda 基座沿用 `[-0.6, 0, 0]` m 与世界四元数 wxyz `[1, 0, 0, 0]`。使用命名映射登记 `robot0_joint1…robot0_joint7`、两个手指关节、七个机械臂力矩执行器及两个夹爪执行器，禁止依赖 MuJoCo 数字索引跨模型一致。固定 `gripper0_grip_site` 为 OSC 使用的末端控制站点，并保留腕部相机挂载与外部 `agentview`，供 Step 5 核对。
3. 在原始环境用与 Step 2 相同的初态索引 0–4 导出机器人及物体的命名位姿、速度和所需控制器初值。记录 `set_init_state` 后及官方预热后的快照。WSim 重置按名称恢复原始预热结束快照的世界、本体、OSC 目标及夹爪累积状态，控制计数和 WSim 时钟归零。每个索引使用对应快照，不跨模型直接复制整段 `qpos/qvel`。
4. 新增 Panda 本体注册与专用的带机器人 Scenario，建议基础名为 `libero-object-alphabet-soup-panda`，用 `-init-1` 至 `-init-4` 选择其他初态。保留 Step 2 的无机器人版本作为回归。Panda 只能在含匹配 MJCF 的 Scenario 中选用，加载前核验配置。复用现有 Scenario 驱动的本体识别和 ER 启停机制，Panda profile 只声明已实现的本体反馈与受控入口。验证版用固定动作客户端取得控制权，旧技能路由不得成为 Panda 的运动入口。

资产、初态映射、运行配置及测试入口集中在 `steward/`。报告记录固定源码版本、许可证、资产校验值、有效物理参数和启动方式。若直接复用控制器代码，记录来源和改动，限制依赖在世界侧控制模块。若 robosuite 1.4.1 的接口与 Steward MuJoCo 不兼容，先用小试验验证窄适配；需要移植时，按原始实现对照目标、力矩和闭环轨迹，达到同一验收口径。

## 3. OSC 与物理夹爪

| 项目 | 实现与对照 |
| --- | --- |
| 归一化动作 | 固定 7 个有限值。前 3 项是世界系 xyz 增量，后 3 项是轴角增量，最后 1 项是夹爪命令。控制器按原版限幅和缩放。 |
| 位置与朝向 | 分量裁剪至 `[-1,1]` 后分别按 0.05 m、0.5 rad 缩放；平移加到当前末端站点，非零旋转增量左乘当前末端朝向，零旋转保留上一周期的朝向目标。 |
| OSC 配置 | 固定 robosuite 1.4.1 的 `OSC_POSE`，`kp=150`、`damping_ratio=1`、固定阻抗、位置与朝向解耦、增量模式、无插值。导出有效限幅、Jacobian 与关节姿态参考的配置来源。 |
| 仿真调度 | WSim 每 0.002 s 推进一步，控制周期为 0.05 s，即 25 个物理子步。每条动作仅在周期开始更新一次目标。随后每个物理子步按原版时序重算力矩，裁剪至执行器限幅再写入命名执行器。 |
| 夹爪 | 保留 PandaGripper 的符号和累积规律，负值打开、正值闭合、零保持累计目标。按原版夹爪子步更新和执行器范围映射到双指，核对两个执行器分别响应。 |
| 反馈 | 记录目标与实际末端位姿、七关节位置速度、双指位置、执行器控制量和仿真步。机器人端口只返回本体反馈与控制状态。 |

先在[原始 LIBERO 环境](step1.md)采集固定动作的每周期目标和每子步控制量，再接到 WSim 的物理步推进点。Panda 走专用 OSC 与真实双指执行器通道，旧 `joints`、`gripper`、`_try_attach` 和 `_follow_attached` 路径不得代替这一通道。旧本体仍使用其原有控制方式。

## 4. 执行器控制权

- 在机器人端口增加独占执行器租约。每条动作提交与每次实际应用都核对 `episodeId`、`controlGeneration` 和有效租约。租约用单调墙钟计时，和控制仿真推进的 hold 分开。
- WSim 在同一临界区校验、排队、取出动作与撤销控制。单动作测试入口建议每次仅有一条待执行动作，用单调序号拒绝重放。提交确认与实际应用记录分开，记录应用的周期和起止步。
- 显式停止、执行器租约到期、Episode 重置或切换时，清除尚未应用的动作并使旧代次失效。在下一物理步前切入已验证的安全保持状态。候选保持方式是以当前末端姿态为目标，受限阻尼保持，并冻结夹爪目标；以遥测验证后再启用。暂停或时钟 hold 时仍按墙钟判定过期，恢复推进前不得执行旧动作。
- 明确区分撤销确认与物理停止确认。只有取得撤销确认且关节、末端速度进入预先冻结的阈值并持续指定窗口，才报告已停止。确认超时返回状态未知，禁止接续旧执行。重复停止、迟到动作和旧租约续租均需覆盖。Step 7 从 EH 端复验同一协议。

## 5. 验证与验收

| 验收项 | 方法与证据 |
| --- | --- |
| 加载与重置 | 通过正常 Steward 控制台加载带 Panda 的 Scenario，初态 0–4 均能加载和重复重置。检查本体登记、七关节和九个执行器映射、工具站点与无机器人 Step 2 场景的回归。保留控制台截图、实际命令和初态差异表。 |
| 单轴控制 | 在空中安全姿态对 xyz 与三个轴角分别发出正负小幅动作，并做零动作与边界值测试。比较源环境与 WSim 的目标位姿、实际移动方向、幅度、控制量及饱和情况。轴角对比采用姿态误差，不能只比欧拉角。 |
| 连续控制 | 用同一组至少包含平移、转动和停止的固定动作，在源环境与 WSim 从相同初态重放。比较每周期末端位置和朝向、关节轨迹、力矩与漂移。核对 25 个子步和目标只更新一次。 |
| 夹爪 | 空中执行开、合、保持与反向开合，比较双指位置、开口宽度、耗时及限位。验证无接触的合爪不会产生理想附着。录像同时展示机械臂与双指。 |
| 停止与失联 | 通过机器人端口实测停止、墙钟租约到期、时钟冻结后过期、重置后迟到动作和新代次接管。验证停控后执行日志没有旧动作，并检查停止后的速度及夹爪目标。 |
| 输入与旧本体回归 | 无效维度、非有限值、越界策略按接口规则处理，拒绝请求不修改控制状态。现有厨房与 Cobot 的普通命令、加载和重置走原入口回归。 |

正式跑批前，先量测原始环境重复运行的轨迹差异，冻结初态、动作序列、采样时刻、方向判断、位置与姿态误差、力矩和停止阈值。保留源环境和 Steward 的完整轨迹、配置哈希、诊断日志及录像。先验证命名映射和单周期一致性，再进入连续轨迹和停止验收。报告需分别标明资产编译、真实控制、生命周期三类结果。
