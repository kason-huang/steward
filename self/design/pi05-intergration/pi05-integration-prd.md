# Steward π0.5 接入 PRD

需求基线：2026-11-09。2026-11-13 已完成指定汤罐场景初态 0 的单例完整链路，当前技术方案与验收边界由[接入设计](pi05-integration-design.md)维护。下述问题背景描述接入前状态，产品要求仍作为验收依据。本文定义产品目标和范围，技术细节见[接入设计](pi05-integration-design.md)，所有实现遵守 [Steward 设计说明](../../../steward.md)。

## Problem Statement

- **当前策略包含 LLM 程序与规则技能两层。** EH 可通过 `run_code` 编写组合机器人工具的程序，保存到机器人能力库并在后续任务中复用或修订。ER 的基础 `pick`、`place` 等技能由几何规划和手写控制流程实现。π0.5 接入针对根据连续图像和本体反馈生成动作的执行能力。
- **当前抓取使用理想附着。** 夹爪闭合时，WSim 按几何条件选中物体，使其刚性跟随夹爪；普通附着物体关闭碰撞，可倾倒容器保留碰撞。这可以验证任务编排，但不能验证通过接触、夹持力与摩擦维持抓持，以及滑移、掉落等物理结果。
- **两种现有本体已共用技能入口。** `steward-bot` 与 Cobot Magic 均通过 `steward ego --body <id>` 运行同一 Ego Runtime，提供预测、技能执行与控制权接口。Cobot 经 `PiperArm` 将平面臂命令转换为本体动作；其脚本任务另由 `steward cobot` 运行。新增 LIBERO 本体仍需核对配套控制器、观测和策略适配。
- **理想附着与本体专用技能限制了验证范围。** 两种现有本体均使用理想附着，其任务成功不能代表真实接触操作能力，也不能作为 π0.5 成功率。新增机器人应复用已有装配、关节控制和运动学能力，补足配套控制器、物理抓取、安全预测和 EH 技能入口，不沿用不适用的本体专用技能。
- **现有本体与 π0.5 权重不直接匹配。** `steward_bot` 使用移动底盘、升降、伸缩和两轴手腕，不能假定兼容现成权重所需的机器人机构、相机、本体状态和动作定义。Cobot Magic 的双 Piper 机构也不能据此视为匹配 π0.5-LIBERO。场景资产、观测编码、控制器与安全预测仍须按配套基线验证，单独连接推理服务不能解决这些差距。
- **成功率测试需要配套组合。** 从零引入 π0.5，需要同时具备可用模型、模型支持的任务场景和对应机器人，并能重置初态、重复运行和判断成功。现有规则技能的成功或一次模型调用成功，都不足以证明 π0.5 的任务成功率。

## Solution

- **使用 LIBERO 的配套机器人。** 从 [LIBERO](https://github.com/Lifelong-Robot-Learning/LIBERO) 选择一个任务场景，将其对应机器人、夹爪、控制器和传感器配置复刻到 Steward；保留原有 `steward_bot`，首期不要求现成权重控制旧本体。
- **复用已有权重和场景，避免引入训练工程。** 使用 OpenPI 的 π0.5-LIBERO 权重，配置名为 `pi05_libero`，官方权重地址为 `gs://openpi-assets/checkpoints/pi05_libero/`（[官方说明](https://github.com/Physical-Intelligence/openpi/blob/main/examples/libero/README.md#results)）。选择该权重支持、具有明确成功判据的 LIBERO 任务，复用其场景资产、初态、观测与动作配置，减少本体和任务迁移差异。具体任务 ID 和资产版本通过原始环境基线核实后固定。
- **接入现有技能调用链。** 沿用 EH → `ctx.ego` → Ego API → ER，由 EH 提交目标与约束，ER 在一个技能 Job 内持续观测、调用 π0.5、检查并执行动作，直到完整任务结束。策略张量与本体控制的转换集中在 ER，EH 保持统一的预测、执行、查询和停止语义。
- **通过物理接触完成操作。** 新本体依靠夹爪接触、摩擦、重力和惯性完成抓取、搬运与释放，保留抓空、滑移、掉落和碰撞结果。不得通过理想附着、改写物体位姿、关闭碰撞或释放时清零速度替代物理操作。
- **在 Steward 内测量成功率。** 先跑原始 LIBERO 任务作为基线，再在复刻场景中重复执行同一任务，报告成功次数、总次数、成功率和失败原因。机器人依据传感器与 ES 判断完成，世界侧独立使用 GT 评估；GT 不进入机器人执行与恢复决策。
- **限定首期范围。** 只覆盖一个选定任务、对应机器人和场景，不包含 ACT 过渡、数据采集与训练、全量 LIBERO 基准、任意任务泛化、真实硬件或多技能连续编排。若配套组合不可用，记录差距并提出范围变更。

## 验收要求

1. EH 经真实 ego profile 和现有工具链发起任务，真实 π0.5 驱动 Steward 内的机器人完成完整操作，保存图像或录像及执行记录。测试替身只验证接口与故障路径。
2. 单次功能通过要求同一 Episode 中 Job 为 `succeeded`、机器人判断为 `achieved`、世界侧确认目标达成，且安全检查与信息隔离成立。执行结束或达到预算不能直接算成功。
3. 在运行前固定多 Episode 的初态集合、次数、种子、模型与控制配置、执行预算及计数规则，保留全部尝试，分别报告物理成功率与完整链路功能通过率。具体口径见[成功率评测](pi05-integration-design.md#104-成功率评测口径)；最低通过率尚未约定。
4. 验证取消、超时、断连、非法动作、迟到结果和预测拒绝，确认不再下发失效动作；停止无法确认时报告未知状态并阻止后续执行。
5. 保留预测凭据、ER 动作检查、GT 隔离和既有本体回归。不修改上游 Harness、主循环、会话格式、根工作区或上游检查脚本；DSH 依赖集中在 Steward 适配工作区，Node 应用经命名 profile 启动。

## 实施前需固定

- Linux NVIDIA GPU 环境、OpenPI 与权重版本、依赖及资产许可。
- 一个 LIBERO 任务的 ID、原始指令、场景、机器人、初态集合和两侧完成条件。
- 相机与状态编码、动作映射、控制节奏、时钟模式、预测覆盖和执行预算。
- 评测次数与统计配置。当前尚无真实 GPU 运行或成功率结果。

实施检查点见[实施计划](pi05-integration-plan.md)，现有实现差距见[差距分析](pi05-integration-gaps.md)。
