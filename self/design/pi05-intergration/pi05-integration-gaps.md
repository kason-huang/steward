# Steward π0.5 接入差距分析

日期：2026-11-06。状态：待验证。需求与方案见 [接入 PRD](pi05-integration-prd.md)和[接入设计](pi05-integration-design.md)。

## 本次目标

本次只有一个阶段：EH 经现有技能工具提交一条受支持的完整任务，例如“把物体抓起并放入容器”，ER 在一个技能 Job 内调用 π0.5、执行动作并判断结束。策略在任务中可以多次观测和推理，验收需要完整任务成功记录和固定批次的成功率报告，统计口径见[接入设计 §10.4](pi05-integration-design.md#104-成功率评测口径)。

## 必须补齐的差距

| 差距 | 当前情况 | 本次需要完成 |
| --- | --- | --- |
| 权重与任务 | 确定使用 `pi05_libero`，尚无本地运行结果 | 固定版本、原始任务指令和初态，在 GPU 机器上跑通配套示例 |
| 本体与世界 | 已支持按 Scenario 装配 `steward-bot` 或 Cobot Magic 的独立 ER，两者均未验证兼容 π0.5-LIBERO | 选择配套机器人、夹爪、控制器和最小场景，确定迁入 WSim 或纳入 Steward 世界侧管理的路线 |
| 物理抓取 | 两种现有本体的夹爪仍按几何规则附着物体，物体刚性跟随 | 新本体通过接触、夹持力与摩擦抓持，允许抓空、滑移和掉落；释放后由物理引擎计算运动 |
| 策略观测与动作 | 已有 RobotLink、通用关节命令、多夹爪与运动链相机变换，尚无 LIBERO 策略映射 | 对齐相机、状态编码、预处理、动作尺度、坐标系和控制周期，记录输入输出与实际应用动作 |
| 完成判断 | 现有 `holding` 包含仿真附着状态，新任务的完成依据待验证 | 依据机器人图像与本体反馈判断目标达成，世界侧另用 GT 核对，评估结果保持隔离 |
| EH 技能入口 | 移动机器人已有完整技能 API；Cobot 只读 API 尚无预测、控制权与 `/skill/*` | 为选定本体接通凭据、Job、查询、停止和真实 profile 守卫，不以脚本任务替代 |
| 安全与停止 | 现有 ESim 面向旧本体；时钟 hold 租约不保护执行器，命令尚无 Episode、控制代次与执行器租约校验 | 为选定任务限定授权范围与执行预算，检查候选动作；验证取消、超时和迟到响应不会继续运动，并确认停止结果 |

当前实现可核对 [技能执行器](../../../steward/src/steward/ego/skills.py)、[ESim](../../../steward/src/steward/ego/esim.py)、[WSim](../../../steward/src/steward/world/sim.py)和 [MJCF 编译器](../../../steward/src/steward/scene/mjcf.py)。字段、控制器及故障处理的详细要求由接入设计维护。

## 实施顺序与通过条件

1. 在 Linux NVIDIA 机器上固定权重和配套环境，验证一条原始任务指令。
2. 将该任务的机器人、场景、传感器和控制器接入 Steward，核对动作与物理抓取。
3. 接入 ER 策略执行，通过现有预测、运行、查询和停止工具贯通真实 profile。
4. 保存一次完整任务成功的图像或录像、策略与动作记录、机器人完成证据和世界侧评估。另行验证执行中取消与一次推理故障，保留全部尝试及失败记录。

功能通过要求同一 Episode 中 Job 为 `succeeded`、机器人目标结论为 `achieved`、世界侧确认目标达成，且安全检查和信息隔离成立。EH 拆分并编排多个策略技能、第二步从第一步末态继续执行留待后续；选定任务的成功率评测属于首期交付。

当前尚未运行真实 GPU 策略或 Steward 内的完整任务验收，具体本体资产、任务及运行参数仍需实测冻结。
