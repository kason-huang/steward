# Steward π0.5 接入实施计划

日期：2026-11-05。状态：待实施。目标与技术要求分别见 [接入 PRD](pi05-integration-prd.md)和[接入设计](pi05-integration-design.md)，待核实事项见[差距分析](pi05-integration-gaps.md)。

本计划围绕一个交付目标展开：EH 发起一个技能 Job，由 ER 使用真实 π0.5 在 Steward 中完成一次完整任务。以下八步是实现进度检查点。实现、运行配置、场景资产和测试集中在 `steward/`，每一步保留可重复运行的入口、固定配置和截图或录像。

## 1. 跑通原始 LIBERO 任务

在 Linux NVIDIA GPU 机器上搭建 OpenPI 与配套 LIBERO 环境，加载 `pi05_libero`。首选验证 LIBERO Object 中“把指定物品放入篮子”的完整任务，具体任务 ID、物品及初态在本步固定。

- **交付物**包括 GPU 环境记录、依赖版本、权重标识、任务指令、初态和启动方式。
- **可见进展**是原始 LIBERO 环境中机器人执行任务的录像。
- **通过条件**是在固定配置下取得一次完整任务成功，保留全部尝试与失败记录，确认候选权重和任务可运行。

## 2. 将测试场景纳入 Steward

核对场景资产和控制器的兼容性，确定将配套资产迁入现有 WSim，或将配套仿真组件纳入 Steward 世界侧管理。接入选定任务的桌面、物品、篮子和灯光，固定场景初态与重置入口。

- **交付物**是世界侧实现路线、最小 Scenario、资产及加载配置。
- **可见进展**是在 Steward 中加载、查看和重置测试场景，物品能够在重力作用下落到桌面。
- **通过条件**是碰撞、比例和初态正确，篮子具有实际内部空间，能够承托放入的物体。

## 3. 放入配套机器人

加入与权重匹配的机械臂、夹爪、执行器和控制器，配置初始姿态、限位、工具坐标及控制周期。通过 Steward 自有测试入口核对单轴运动和夹爪开合。

- **交付物**是机器人资产、本体配置、控制器配置及动作映射表。
- **可见进展**是在测试场景中看到机器人，能够移动末端和开合夹爪。
- **通过条件**是运动方向、尺度和参考系正确，连续动作下的轨迹及控制响应与配套基线一致。

在接入策略前验证机器人端口层的停止、控制租约到期和 Episode 重置，确认旧命令失效。第 7 步再验证这些行为通过 EH 工具入口同样生效。

## 4. 跑通物理抓取

用固定测试动作验证夹爪接触、摩擦、物体碰撞和自然释放。正常抓取与抓空、偏位、夹持不足及携物碰撞均保留实际物理结果。

- **交付物**是固定动作测试入口、物理参数和抓放记录。
- **可见进展**是夹爪将物体夹起、搬运并放下，松开后物体自然运动。
- **通过条件**是抓持由接触维持，偏位时允许抓空，携物碰撞有效，放入篮子的物体由其底面承托。新路径不调用旧本体的理想附着机制。

## 5. 接通机器人观测

通过机器人传感器通道提供外部视角、腕部相机、关节和夹爪反馈，按固定版本实现图像预处理与状态编码。核对相机访问符合信息隔离要求，本体位姿计算使用机器人测量与已知运动学。

- **交付物**是观测适配、逐字段规格、同步检查和传感器预览入口。
- **可见进展**是能够查看策略实际收到的两路图像及状态，腕部视角随机械臂运动。
- **通过条件**是时间、图像方向、状态顺序与参考系正确，策略输入不包含 GT 对象身份、真实物体位姿或隐藏成功信号。

本步同时验证任务物体能够被机器人侧感知识别并保持 ES 引用，且相机与本体反馈足以支持完成判定。先用第 4 步的固定动作采集完成与失败样例，核实放置后的物体可见性和关联；观测不足时先调整方案，再进入策略集成。

## 6. 接入 π0.5 闭环执行

在 ER 技能执行侧接入远程策略服务，执行有限动作前缀后重新采样和推理。同步实现预测授权、响应校验、动作安全检查、时钟协调、执行预算和取消处置，再开放运动路径。

- **交付物**是策略适配与调度、选定任务的动作检查，以及输入、输出和实际应用动作记录。
- **可见进展**是 π0.5 在 Steward 场景中连续控制机器人，运行记录可区分等待推理、执行动作和安全拒绝。
- **通过条件**是动作经授权和检查后执行，超时、非法输出、旧观测与迟到响应按设计处置，能够诊断操作失败发生在哪个环节。

记录模型及配置版本、观测引用、实际推理输入、已应用动作和仿真时刻，并保留停止与取消边界。用记录的动作验证重放，核对固定初态下的轨迹及物理结果，误差与运行条件按接入设计明确。

## 7. 接通 EH 工具与停止

贯通真实 ego profile、`ctx.ego`、Ego API 和 ER Job，验证预测、运行、状态查询与停止。操作员停止和推理故障都进入统一的动作失效与停止确认流程。

- **交付物**是工具适配、任务能力说明和完整调用链的故障验证记录。
- **可见进展**是从聊天入口提交任务，查看 Job 与机器人运动，并通过现有停止入口中断执行。
- **通过条件**是凭据拒绝时无运动，停止后旧命令失效，停止结果可确认。确认失败时明确报告未知状态，阻止后续控制。

## 8. 完成判断与最终验收

建立选定任务的机器人侧完成判定，世界侧使用 GT 独立核对。完成判定根据视觉和本体反馈形成证据，遮挡或关联歧义返回未确认。若本步发现观测不足，回到第 5 步调整并复验。

- **交付物**是机器人完成证据、世界侧评估、完整执行记录和成功录像。
- **可见进展**是 EH 发起一次任务，机器人完成抓放并报告成功，实验员可查看独立评估与录像。
- **通过条件**是在同一 Episode 中，Job 为 `succeeded`、机器人目标结论为 `achieved`、世界侧确认目标达成，安全检查与信息隔离成立。另行验证一次执行中取消与一次推理故障。

按修改范围运行 Steward Python 测试、DSH 适配编译与测试、真实组合配置检查，以及旧本体与原有场景回归。核对新技能结果进入模型会话记录、通用工具禁用配置和 GT 隔离，并保存实际执行的检查结果。

## 进度记录

每一步以可运行的结果和证据确认完成。第 4 步固定动作验证机器人与物理控制，第 6 步验证策略闭环，第 8 步完成产品验收。出现失败时保留最后可确认的状态和记录，修复后重新验证受影响检查点。一次成功用于证明该任务链路贯通，批量成功率和跨任务能力按后续范围安排。
