# Steward π0.5 接入实施计划

日期：2026-11-06。状态：待实施。目标与技术要求分别见 [接入 PRD](pi05-integration-prd.md)和[接入设计](pi05-integration-design.md)，待核实事项见[差距分析](pi05-integration-gaps.md)。

本计划围绕一个交付目标展开：使用 π0.5-LIBERO，将 LIBERO 中一个任务场景及对应机器人复刻到 Steward；EH 每次发起一个技能 Job，由 ER 使用真实 π0.5 完成完整任务，并在固定批次中测量成功率。以下八步是实现进度检查点。实现、运行配置、场景资产和测试集中在 `steward/`，每一步保留可重复运行的入口、固定配置和截图或录像。复用已有权重与配套组合，首期不开展数据采集或训练；路线与范围见 [PRD Solution](pi05-integration-prd.md#solution)。

## 1. 跑通原始 LIBERO 任务

在 Linux NVIDIA GPU 机器上搭建 OpenPI 与配套 LIBERO 环境，加载 `pi05_libero`。从该权重支持的 LIBERO 任务中选择一个场景及对应机器人；可优先核实 LIBERO Object 中“把指定物品放入篮子”的任务，具体任务 ID、机器人、物品及初态在本步固定。

- **交付物**包括 GPU 环境记录、依赖版本、权重标识、任务与机器人资产清单、原始指令、初态集合、启动方式及原始环境成功率报告。
- **可见进展**是原始 LIBERO 环境中机器人执行任务的录像。
- **通过条件**是取得完整任务成功证据，并在预先固定的初态集合与批次上记录成功次数、总次数和成功率，确认配套组合可运行；保留失败与人工干预记录。

## 2. 将测试场景纳入 Steward

核对场景资产和控制器的兼容性，确定将配套资产迁入现有 WSim，或将配套仿真组件纳入 Steward 世界侧管理。复用选定 LIBERO 场景的资产、布局和接触参数，接入任务所需的工作台、物体及目标区域，固定与原始基线对应的初态集合与重置入口。

- **交付物**是世界侧实现路线、最小 Scenario、资产及加载配置。
- **可见进展**是在 Steward 中加载、查看和重置测试场景，物品能够在重力作用下落到桌面。
- **通过条件**是碰撞、比例和初态正确，若任务涉及容器，其具有实际内部空间并能承托物体。

## 3. 放入配套机器人

复用第 1 步确定的 LIBERO 机器人、夹爪、执行器和控制器，配置初始姿态、限位、工具坐标及控制周期。沿用本体注册表和按 Scenario 启停独立 ER 的机制，登记选定本体及运行配置；复用适用的通用关节与多夹爪命令，通过 Steward 自有测试入口核对单轴运动和夹爪开合。

- **交付物**是机器人资产、本体配置、控制器配置及动作映射表。
- **可见进展**是在测试场景中看到机器人，能够移动末端和开合夹爪。
- **通过条件**是运动方向、尺度和参考系正确，连续动作下的轨迹及控制响应与配套基线一致。

机器人端口需新增 Episode、控制代次与执行器租约校验，不能用已有时钟 hold 租约替代。在接入策略前验证停止、控制租约到期和 Episode 重置，确认旧命令失效。第 7 步再验证这些行为通过 EH 工具入口同样生效。

## 4. 跑通物理抓取

用固定测试动作验证夹爪接触、摩擦、物体碰撞和自然释放。正常抓取与抓空、偏位、夹持不足及携物碰撞均保留实际物理结果。

- **交付物**是固定动作测试入口、物理参数和抓放记录。
- **可见进展**是夹爪将物体夹起、搬运并放下，松开后物体自然运动。
- **通过条件**是抓持由接触维持，偏位时允许抓空，携物碰撞有效，放入篮子的物体由其底面承托。新路径不调用旧本体的理想附着机制。

## 5. 接通机器人观测

通过机器人传感器通道提供外部视角、腕部相机、关节和夹爪反馈，按固定版本实现图像预处理与状态编码。复用估计器已有的关节树前向运动学，核对新本体的关节映射、腕部相机标定与采样同步；相机访问符合信息隔离要求，本体位姿计算使用机器人测量与已知运动学。

- **交付物**是观测适配、逐字段规格、同步检查和传感器预览入口。
- **可见进展**是能够查看策略实际收到的两路图像及状态，腕部视角随机械臂运动。
- **通过条件**是时间、图像方向、状态顺序与参考系正确，策略输入不包含 GT 对象身份、真实物体位姿或隐藏成功信号。

本步同时验证任务物体能够被机器人侧感知识别并保持 ES 引用，且相机与本体反馈足以支持完成判定。先用第 4 步的固定动作采集完成与失败样例，核实放置后的物体可见性和关联；观测不足时先调整方案，再进入策略集成。

## 6. 接入 π0.5 闭环执行

在 ER 技能执行侧接入远程策略服务，执行有限动作前缀后重新采样和推理。同步实现预测授权、响应校验、动作安全检查、时钟协调、执行预算和取消处置，再开放运动路径。

- **交付物**是策略适配与调度、选定任务的动作检查，以及输入、输出和实际应用动作记录。
- **可见进展**是 π0.5 在 Steward 场景中连续控制机器人，运行记录可区分等待推理、执行动作和安全拒绝。
- **通过条件**是动作经授权和检查后执行，超时、非法输出、旧观测与迟到响应按设计处置，能够诊断操作失败发生在哪个环节。

记录模型及配置版本、观测引用、实际推理输入、已应用动作和仿真时刻，并保留停止与取消边界。用记录的动作验证重放，核对固定初态下的轨迹及物理结果，误差与运行条件按接入设计明确。

## 7. 接通 EH 工具与停止

为选定本体接通完整技能 API，再贯通真实 ego profile、`ctx.ego`、Ego API 和 ER Job，验证预测、控制权、运行、状态查询与停止。Cobot 现有只读 API 与内置脚本任务不代表此链路已贯通。操作员停止和推理故障都进入统一的动作失效与停止确认流程。

- **交付物**是工具适配、任务能力说明和完整调用链的故障验证记录。
- **可见进展**是从聊天入口提交任务，查看 Job 与机器人运动，并通过现有停止入口中断执行。
- **通过条件**是凭据拒绝时无运动，停止后旧命令失效，停止结果可确认。确认失败时明确报告未知状态，阻止后续控制。

## 8. 完成判断与成功率验收

建立选定任务的机器人侧完成判定，世界侧使用 GT 独立核对。完成判定根据视觉和本体反馈形成证据，遮挡或关联歧义返回未确认。若本步发现观测不足，回到第 5 步调整并复验。

按[接入设计 §10.4](pi05-integration-design.md#104-成功率评测口径)在运行前固定 Episode 数、初态列表、种子、执行预算和计数规则。重复运行选定任务，对照第 1 步的原始基线，分别报告世界侧物理成功率和完整链路功能通过率，并说明仿真、时钟与安全限制的差异。失败和人工干预不删样，额外注入的取消、故障测试单独报告。

- **交付物**是机器人完成证据、世界侧评估、完整执行记录、成功录像和固定批次成功率报告。
- **可见进展**是 EH 发起一次任务，机器人完成抓放并报告成功，实验员可查看每次执行的独立评估、录像及整批成功率。
- **通过条件**是在同一 Episode 中，Job 为 `succeeded`、机器人目标结论为 `achieved`、世界侧确认目标达成，安全检查与信息隔离成立；并完成固定批次重复评测，报告两类成功次数、总次数及成功率。最低通过率尚未约定，不以官方基准成绩代替本地结果。另行验证一次执行中取消与一次推理故障。

按修改范围运行 Steward Python 测试、DSH 适配编译与测试、真实组合配置检查，以及旧本体与原有场景回归。核对新技能结果进入模型会话记录、通用工具禁用配置和 GT 隔离，并保存实际执行的检查结果。

## 进度记录

每一步以可运行的结果和证据确认完成。第 4 步固定动作验证机器人与物理控制，第 6 步验证策略闭环，第 8 步完成产品验收。出现失败时保留最后可确认的状态和记录，修复后重新验证受影响检查点。一次成功用于证明该任务链路贯通；选定任务的成功率评测属于本次验收，全量基准与跨任务能力按后续范围安排。
