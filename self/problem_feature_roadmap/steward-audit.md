# Steward 缺陷与改进清单

审查版本为 `a6bfea9376`，范围为 `./steward`。建议优先修复场景保存越界、重置后旧任务继续发送动作，以及非法倍速导致仿真停摆。这三项分别影响本地文件、Episode 隔离和仿真可用性。

## 已确认的缺陷

1. **P1 · 场景保存可以覆盖数据目录之外的 JSON 文件。** 在隔离实例中，向 `/scenarios/save` 提交场景名 `../../escaped`，服务返回 200，并覆盖了数据根目录外的测试文件。接口也接受带外部 `Origin` 的 `text/plain` 请求，浏览器跨站触发未单独验证。限制场景名，验证解析后的路径仍在目标目录内，并给写接口增加来源校验和授权。定位：`authoring/service.py:234`、`net.py:76`。
2. **P1 · Cobot 重置后，旧任务仍会发送运动指令。** 用受控传感器输入让仿真时间从 10 秒跳回 0 秒。运行时检测到重置，但旧移动仍发出 `base: [-2.5, 0, 0]`。让 Episode 标识随传感器和动作传递，在世界端拒绝旧 Episode 的命令，并在重置时取消旧技能。定位：`ego/cobot_runtime.py:72`、`ego/cobot_skills.py:343`。
3. **P1 · 非法倍速能让物理线程退出。** `/wca/clock` 接受字符串 `"nan"`，先写入仿真状态，随后返回 500。物理线程因数值转换异常退出，再设回 `1` 也不会恢复。CLI 和 API 应共用校验，只接受有限正数及显式的 `max`，并向控制台报告物理线程退出。定位：`world/server.py:367`、`world/sim.py:506`。
4. **P2 · 写请求返回 503 后仍可能执行。** 等待超时的主线程请求仍留在队列里。复现中，调用方先收到 503，随后 `pump()` 执行了该操作。重试加载、重置或编辑时，两次操作都可能生效。取消尚未开始的任务，为已开始的操作提供可查询的结果。定位：`world/server.py:233`。
5. **P2 · 切换感知阶段失败后留下部分新状态。** 缺少名称映射时，从 `phase1` 切换到 `phase0-misnamed` 返回 400，但当前阶段、后续 Episode 的固定阶段和传感器模式均已改变。先解析并校验全部配置，再一次性提交。定位：`world/server.py:199`。
6. **P2 · 技能因忙碌未启动，预测凭据仍被消耗。** 已有技能运行时，首次提交得到“上一技能仍在运行”，再次提交同一凭据却得到“已执行”。在执行器成功接纳任务时原子地消耗凭据。定位：`ego/runtime.py:1402`、`ego/skills.py:160`。
7. **P2 · 只提供自我态的机器人被标记为可接任务。** `attach_ego_api(..., skills=False)` 写入了拒绝原因，但聊天可用性检查未读取它。用已配置 profile 的测试对象复现，机器人仍被判定可用。让聊天和任务派发读取同一个能力状态。定位：`world/server.py:267`、`world/chat.py:199`。
8. **P2 · 资产名与版本可以错配。** 用 `black-mug` 的名称和 `bowl` 的版本查询，实际返回了碗。场景组合会沿用请求里的资产名，导致几何与资产引用不一致。查询时应验证版本属于指定资产。定位：`assets/library.py:77`、`authoring/service.py:77`。

上述源码位置均相对于 [steward/src/steward](../../steward/src/steward/)。

## 改进建议

1. **让控制台保留操作失败的反馈。** Chrome 中，聊天未配置时仍显示操作控件，状态栏为空。源码显示，成功的状态轮询会清掉共享错误提示，加载或聊天失败的原因可能很快消失。显示明确的禁用原因，并把操作错误放在触发它的控件旁。[状态轮询与聊天界面](../../steward/src/steward/world/console.html)
2. **将 Episode 切换作为一次状态变更管理。** 当前加载先设置本体、停止旧回合，再尝试构建新世界。机器人进程的重建发生在世界启动之后。先验证目标，串行化加载和重置，并明确区分“切换失败”和“世界已加载、机器人启动失败”。[Episode 加载](../../steward/src/steward/world/server.py) · [Ego 进程管理](../../steward/src/steward/cli.py)
3. **明确多标签页是否共享视角。** 每个页面每五秒提交自己的相机和帧率，后端只有一份设置。按现有代码，两页使用不同视角时会互相覆盖。若需要独立观察，按查看者管理设置。若设计上共享，在界面标明并限制谁可以写入。[页面定时提交](../../steward/src/steward/world/console.html) · [后端视图设置](../../steward/src/steward/world/server.py)
4. **给 Steward 增加独立的 CI 检查。** 本地脚本已覆盖 Python、DSH 插件和配置快照，现有工作流中未找到 Steward 专项入口。先接入无需模型密钥的 HTTP、Episode、凭据和插件测试，再单独安排耗时的 MuJoCo 任务。[本地检查脚本](../../steward/scripts/check.sh) · [现有 Python CI](../../.github/workflows/ci-python.yml)

## 验证范围

Chrome 实测加载了世界、自我态和两路相机画面，并操作了标签开关和聊天目标切换。Python 快速测试 20 项通过。两组更广的测试分别运行到 37 项和 11 项通过后中止，完整套件没有结果。DSH 插件和远程感知服务仅做了源码检查。审查期间未修改代码。
