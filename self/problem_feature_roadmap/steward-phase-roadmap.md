## 阶段总览

WSim 推进世界，WS 记录世界真实状态。机器人根据当前功能级别提供的观测构建 ES，ESim 根据 ES 预测动作后果，ER 执行技能，EH 理解目标并编排技能。WH 管理世界与实验，Observer 独立比较机器人判断和世界实际结果。后续阶段分别增强这些模块，并通过固定实验比较效果。

| 阶段 | 关注的核心问题 | 前提约束与信息来源 | 与真实场景的差异 | 对前面阶段的能力依赖 | 本阶段核心能力 | 已实现阶段实例、提供能力与验证用途 | 验收结论的适用范围 |

| Phase 2 | 在多个可能世界状态及突发变化下，某个动作是否仍能安全执行，何时需要重新预测或停止 | 预测模型来自 ES 的估计几何、关系和部署物性先验。预先固定参数分布、样本数、预测时域、风险阈值、计算预算、本体及允许接触范围。扰动类型、幅度、时机和保护区受实验配置约束。执行端具备撤销、租约和遥测确认，世界时钟占用与执行器保护分别管理。 | 真实环境中的摩擦、质量、接触和人员行为只能部分观测，模型与采样分布会遗漏风险。物理过程持续推进，停止存在通信、制动与惯性延迟。现场扰动难以精确重现，需用实测参数、独立硬件保护和带测量误差的评估校准预测。 | Phase 0 的凭据、控制与回放基础，Phase 1 的任务级几何精度、协方差、存在概率和观测时间 | 基于 ES 物理模型和信念采样预测动作后果，完成风险校准与动态授权。构建控制代次、执行器租约、撤销与停止确认，以及受控扰动、触发器和实验回放。 | 运行级别待登记。现有几何 ESim、风险检查与控制保护的单项结果按实际运行的 Phase 0 或 Phase 1 实例记录，物理推演、信念采样和扰动实验按本阶段计划验收。 | 风险收益限定在已建模事件、采样分布、动作范围与扰动强度内。报告接触简化、参数缺失处理、未覆盖事件、风险校准和计算成本。控制保护需覆盖失联、重置、在途命令和冻结时钟。对照实验固定初态与扰动，机器人依据自身观测发现变化，世界 GT 用于独立评分。 |
| Phase 3 | 如何把目标变成连续接触动作，如何判断完成，如何在多步任务中恢复并继续 | 权重绑定指定本体、相机、状态编码、动作语义和任务分布。原始 LIBERO 基线使用其自带传感器与控制器，可与 Phase 1 开发并行。Steward 内接入采用固定资产与参数的仿真接触动力学。完成条件须可由机器人图像、本体反馈或 ES 关系判定，长任务以前置技能和资源释放验证为基础。 | 实际机器人在机构、相机、控制延迟和标定上可能偏离训练本体，真实物体的摩擦、柔性和夹持条件更复杂。配套仿真任务可固定初态并读取世界成功信号，实机需定义可复位过程及独立完成证据，并重新测量策略成功率。 | Phase 1 的同步图像、本体状态、稳定对象引用与完成证据，Phase 2 的本体动作检查、授权和停止保护，Phase 0 的真实工具调用链 | 接入 VLA/MPC 等操作技能，完成配套本体、控制器和动作适配，在仿真接触中闭环执行。构建机器人侧完成判断、子目标编排、有界恢复与能力复用。 | 运行级别待登记。π0.5 原始 LIBERO 基线作为配套选型的独立实验记录，Steward 内的策略闭环、接触操作与长任务实例随接入和验收登记。 | 原始基线、Steward 单技能与多子目标任务分别验收。报告配套规格和适配差异、碰撞与抓持模式、策略输入及实际动作。物理成功与完整链路成功分别统计，记录未确认、部分效果、人工干预和恢复。跨任务、跨本体及物理参数变化按扩展范围重新评测。 |
| Phase 4 | 多台机器人各自知道什么、由谁完成哪一步，通信和资源冲突时如何继续 | 世界统一推进物理，每台机器人有独立传感器、ER、EH、会话与控制身份。坐标对齐可由部署给定或由机器人估计。预设集中调度或分布式协商、消息权限、延迟、丢包、有效期以及工位和资源占用规则。 | 真实多机具有各自的时钟、定位漂移和通信盲区，共享物体引用与地图需要对齐。电量、负载、速度和制动能力存在差异，现场人员也会占用通道。统一仿真时钟与预设资源规则需要扩展为可处理异步、测量误差及临时障碍的协作机制。 | Phase 0 的多实例隔离，Phase 1 的对象与坐标表达，Phase 2 的控制保护与故障回放，Phase 3 的单机技能和任务恢复 | 为多机器人维护独立 ES、ER/EH 与控制权限，通过显式通信共享带来源和时效的证据。构建任务分配、资源协调、接力与失联恢复，并评估通信故障下的协作表现。 | 运行级别待登记。多机器人装配、通信和资源协调按本阶段计划组合为协作实例，并在登记时明确使用的感知与技能实现。 | 结论对应约定的机器人组合、网络故障和资源竞争范围。共享证据保留来源、坐标误差与时间，报告协调者及各机器人可读信息。分别验证永久失联、重新接入、接力与资源释放，用同任务单机对照衡量协作增益。 |
| Phase 5 | 同一任务体系怎样应对真实传感器、执行延迟、接触误差与硬件故障 | 固定设备、负载、驱动、工作区、物体材质及人员安排，现场硬急停和驱动保护可用。实测相机、关节、安装与工具参数，明确时钟同步、推理位置和网络条件。外部相机、标记或动捕提供独立评估并携带测量误差。 | 本阶段直接面对实机，实验条件仍限定于选定设备、工作区、任务与现场保护。长期运行还会遇到磨损、标定漂移、设备更换、季节光照和人员行为变化。扩大部署范围时需增加持续监测、复标定、故障恢复及相应条件下的重新验收。 | Phase 1 的感知接口与误差评估，Phase 2 的预测和失联处置，Phase 3 的接触技能与完成判断，Phase 0 的部署和记录基础，涉及多机时再依赖 Phase 4 | 通过 Real HAL 接入真实传感器和执行器，完成本体标定、实机感知与仿真匹配。结合独立硬件保护分级迁移操作技能，建立外部评估和可复现部署。 | 运行级别待登记。实机实例随 Real HAL 和设备接入登记，绑定机器人、标定、感知、控制与保护配置，按现场任务验收。 | 验收限定在设备、标定版本、任务、照明与现场条件内，扩大范围时增加批次。记录实际墙钟延迟、动作时刻、保护触发、人工介入和复位过程。外部测量保持评估用途，报告其误差与无效样本规则。改装后复验相关标定和技能，多机实机额外验证协作保护。 |

阶段实例对应代码中可选择的运行功能级别，当前注册了 `phase0`、`phase0-misnamed`、`phase1` 和 `phase1-sam`。同一阶段可以包含多个实例，用于替换特定模块和做对照实验。Scenario 指定场景与任务，本体配置指定机器人，实验同时记录所选实例、Scenario 和本体。表中的“用于验证”描述该实例支持的验证范围，具体通过结果以对应实验记录为准。[功能级别注册表](../../steward/src/steward/phases.py)

每次实验记录功能级别、机器人本体、观测来源、控制方式、定位条件、时钟模式和评估来源，并按总览中的前提限定结论。路线图阶段与运行时功能级别分别记录，具体实现、测试与实验报告关联版本和证据日期。

各阶段以对应任务的能力与证据验收，依赖项需要达到该任务预先约定的精度、时效和安全要求。进入 Phase 3 的单任务集成时，需要先补齐该任务涉及的 Phase 1、Phase 2 能力。单机实机试验依赖感知、控制和操作能力，多机实机试验还需要 Phase 4 的协作保护。

Phase 3 的前置实验可与 Phase 1 开发并行。在原始 LIBERO 环境运行 π0.5 时，使用基准自带的机器人、传感器和控制器，产出模型可用性、成功率及适配规格；这些产物用于后续 Steward 集成。Steward 内的正式策略验收需要补齐观测、安全与记录机制。进度表应分别记录“实现、测试、实验验收”状态和证据日期。

## Phase 0 系统闭环与基线维护

### 阶段目标与已有基础

保持从场景构建到任务执行、世界侧确认的完整闭环，使后续模块有可比较的基线。文档记录了世界构建、搬杯子、循环搬运和家务任务的验收，以及模型经 `run_code` 组合技能的路径。阶段维护以这些实际入口为回归范围。[已有验收记录](../../steward.md#135-已验证)

### 实施检查点与通过条件

1. 固定一个简单 Scenario，经真实 EH 工具链完成任务，并由世界侧确认目标。
2. 加入停止、忙碌拒绝、重置和切换场景的故障实验，核对动作及凭据状态。
3. 在固定初态集合上复跑，保存机器人结果、世界评估、日志和录像。

通过条件是闭环可复现、失败具有可定位原因、世界与机器人权限隔离成立。已有任务的通过记录需要关联对应配置，后续模块替换时以同一基线比较。

## Phase 1 视觉感知与可靠的 ES

### 阶段目标与依赖

机器人从 RGB-D、关节反馈和定位信息建立 ES，输出稳定身份、几何、类别及其不确定度。已有基础包括反投影、有向盒、多帧融合与 `phase1-sam` 接入。学习型分割、外观描述子与几何升级的具体选型和首轮实验由第 13.7 节维护。[感知与泛化](../../steward.md#137-phase-1-感知方法与泛化)

### 工作包

### 实施检查点与通过条件

1. 建立固定 RGB-D 数据集，包含两种渲染风格、不同尺寸材质、遮挡和表外物体，世界真值用于离线评分。
2. 在同一输入上逐项替换分割、语义与关联，分别记录收益和新增错误。
3. 在线运行搬运、叠放与抽屉任务，检查操作前后 ES 的身份和几何稳定性。
4. 对比基线和新场景，确认泛化收益，冻结选定版本并保存服务故障与回放结果。

通过条件是任务所需对象具有足够新且可用的观测，位置与类别误差满足后续操作要求，协方差和存在概率经过校准。指标包括召回、误检、类别准确率、ID 切换、位置尺寸误差、NEES、推理耗时与任务成功率，阈值在评测前确定。

### 实施检查点与通过条件

1. 选择一个具有碰撞或倾覆风险的最小动作，比较 ES 预测和 WSim 实际结果。

3. 验证取消、失联、租约到期、重置和迟到结果的完整控制路径。
4. 在固定扰动序列下比较“完整预测”与“保留必要保护的简化预测”两组，统计任务完成和事故情况。

通过条件是达到预先确定的事故降低目标，同时报告任务成功率、误拒率、扰动发现延迟、恢复耗时和推演成本。只有收到撤销确认并满足本体停止条件，才可报告停止已确认。未知执行状态需要阻止后续依赖动作，直到重新确认。

### 实施检查点与通过条件

1. 取得原始策略基线，完成机器人端口层的本体、控制和停止验证。
2. 用固定动作完成接触抓放，验证正例及抓空、滑移等失败。
3. 经真实 EH、Ego API 和 ER Job 完成一次策略闭环任务，并进行固定批次评测。
4. 组合两个以上相互依赖的子目标，在预设扰动下验证重新观察、恢复和安全结束。

通过条件按两个层级记录。单技能要求物理完成、机器人判断和执行终态一致，并统计全部 Episode。长任务还要统计子目标完成率、整任务完成率、恢复次数、人工干预及总耗时。达到动作预算只形成终止原因，成功需要目标证据。

| 标定与运动学 | 相机、关节、臂座和工具坐标的实测误差如何进入状态估计 | Phase 1 的几何与配准方法、Phase 3 的配套本体模型、可只读采集的 Real HAL | 测量相机内参、手眼外参、臂座、工具坐标和关节偏置 | 标定数据、误差范围和复验流程 |
| 硬件保护 | 模型、网络或主进程故障时，设备能否独立进入可确认的停止状态 | Phase 2 的停止、失联和代次设计，真实驱动保护接口与现场急停条件 | 接通硬急停、驱动保护、软件运动许可、速度限制和独立失联停止 | 每项保护的实测证据，停止未知时阻止继续运动 |
| 实机感知 | 仿真中可观察的目标在现场是否仍能稳定识别和定位 | Phase 1 的感知与评测管线、真实标定和录制集、外部独立测量 | 评估遮挡、运动模糊、透明反光、深度缺失和定位漂移 | 实机录制集与 ES 质量报告，明确可操作物体范围 |
| 仿真匹配 | 真实执行的延迟、负载和接触差异怎样反馈到模型 | Phase 2 的物理参数与预测评估、Phase 3 的控制轨迹、实机测量及安全采样条件 | 识别延迟、摩擦、负载和控制响应差异，按实测校准 WSim 与本体模型 | 参数与轨迹对照，报告剩余误差 |
| 技能迁移 | 已验证的策略或控制器在实机上是否仍能闭环完成任务 | Phase 3 的配套策略与完成判断、本阶段 HAL、标定、感知和硬件保护，Phase 2 的动作检查 | 按低速单轴、空载轨迹、单物体抓放、多子目标顺序开放能力 | 各级动作与故障验证，配置关联到机器人和现场版本 |
| 独立评估 | 实机任务是否完成，外部测量本身有多大误差 | Phase 0 的机器人与评估隔离、Phase 3 的目标规则、外部传感器标定与时间同步 | 采用外部相机、标记或动捕建立带测量误差的评估通道 | 机器人判断与外部测量分开保存，记录评估误差 |
| 运维与复现 | 设备重启、模型断连或人为复位后如何恢复可追踪运行 | Phase 0 的配置和日志、Phase 2 的失联处置、Phase 3 的恢复语义，涉及多机时接入 Phase 4 的通信与资源管理 | 固定部署、凭据、模型位置、录像、日志和复位程序，验证断网与重启 | 可重复任务报告，设备故障、人工干预和恢复完整记录 |

### 实施检查点与通过条件

依次完成只读传感器、独立保护、低速单轴、空载轨迹、单次接触任务和固定批次任务。每一级通过后再扩大动作范围。最终用相同 EH bundle 在选定实机上运行对应的 Phase 3 任务，记录驱动与配置差异、机器人完成判断、独立评估、事故和人工干预。

## 跨阶段安排与近期顺序

### 缺陷修复与基础能力

现有缺陷审查中的路径校验、重置后旧动作、时钟输入、排队请求、凭据消耗和能力状态等问题，应先逐项对照当前版本复验，再确定修复范围与回归。修复结果纳入 Phase 0 基线，Episode 和执行器保护同时作为 Phase 2、Phase 3 的前置工作。[缺陷与改进清单](steward-audit.md)

Protobuf、多语言字段生成和工具附件按实际消费者需求推进。协议迁移需要声明版本及兼容策略，处理旧记录，并更新全部消费者和回放入口。图像进入 EH 时需要记录实际模型输入与图像引用。

### π0.5 专项与阶段依赖

| π0.5 专项步骤 | 对应阶段能力 | 可以开始的条件 |
| --- | --- | --- |
| 原始 LIBERO 基线 | Phase 3 配套选型，可与 Phase 1 开发并行 | GPU、权重、环境与任务许可明确，使用原始环境自带观测与控制器 |
| 场景和本体复刻 | Phase 0 装配、Phase 3 控制 | 固定配套基线和资产规格 |
| 策略观测与完成证据 | Phase 1 | 相机、本体反馈与信息隔离可验证 |
| 动作检查、代次、停止 | Phase 2 | 本体控制可测，世界侧能确认命令应用和撤销 |
| 策略闭环与成功率 | Phase 3 | 观测、安全和记录覆盖选定任务 |

### 建议推进顺序

1. 固定当前回归基线，复验高优先级缺陷，优先处理 Episode、动作与 API 状态一致性。
2. 并行安排独立的调查和实验，包括视觉录制集、感知对照评测、π0.5 原始环境基线。
3. 选定一个任务与本体，补齐该组合需要的观测、控制、停止和机器人侧完成证据。
4. 验证动作预测与接触执行，再进行固定批次任务评测，记录失败原因。
5. 根据单任务结果扩大到长任务、受控扰动、多机器人和实机，各次扩大范围前明确新增条件。

这里的顺序按依赖组织。具体排期需要负责人、算力、硬件与验收阈值确定后再填写。

## 验收记录与待确定参数

每个工作包采用“待设计、待实现、已实现待验证、已验证、受阻”状态，并记录负责人、依赖、版本和证据位置。阶段完成需要汇总任务结果及故障验证。

| 记录项 | 必须明确的内容 |
| --- | --- |
| 范围 | 任务、本体、场景、允许物体、运行模式和已知限制 |
| 配置 | 资产、模型、权重、预处理、控制器、传感器和软件版本 |
| 评测设计 | 初态、种子、Episode 数、墙钟与仿真预算、终止条件 |
| 判定 | 机器人目标结论、Job 终态、世界侧或外部独立评估 |
| 计数 | 失败、超时、人工干预、重试和无效实验的处理规则 |
| 故障 | 取消、断连、迟到结果、重置、停止未知及资源释放 |
| 性能 | 推理、感知、规划与控制耗时，缓存情况及实时或冻结时钟条件 |
| 证据 | 输入观测、已应用动作、日志、录像、测试命令与实际结果 |

各阶段的 Episode 数、最低成功率、允许误差、事故降低目标、延迟预算和协作通信条件仍需项目负责人在实验前确认。已有报告中的单次成功和耗时可作为基线记录，新阶段的指标应在结果产生前固定。
