## 图 4 与图 5：用哪条路径完成任务

论文图 4（第 9 页）描述三种可组合的执行路径。**分层调用**由 S2 请求 ESim 预测，经技能执行器通过 S0 下发动作。**代码策略**可在 `run_code` 中编排已授权的工具。**直接调用 S0** 允许 S2 通过 Ego Runtime 下发明确的本体命令。监控器触发本地保护有独立路径。[论文 §2.1](https://arxiv.org/html/2611.18359v1#S2.SS1)

Console 的「S0 本体接口 · S2 直调」显示当前会话与 Ego API 共同提供的接口。`body_stop` 直接请求停止与保持。`ego_motion_status` 和 `ego_gripper_pose` 读取本体反馈，只读复查期间仍可调用。

PiPER 仿真 profile 可显式开启 `body_set_joints` 和 `body_set_gripper`。关节角以弧度提交，机器人检查会话持有控制权、关节限位和当前运动状态，然后下发给 S0，工具等待实际编码器反馈。这条路径没有碰撞规划，适合发明确的本体调试指令。直调结果可从会话和运行活动查看，确定性回放仍以 `/ego/inputs` 中的输入为准。[profile 配置](deployment.md#运行-bpiper-工作台)

按图 5（第 10 页）验收“把黑盒放到左盘，途中改为右盘”：

| 环节 | 应在回放里看到什么 |
| --- | --- |
| ① 理解意图、② 决定 | 当前用户目标和约束、所依据的观测、选择技能或先补看的理由。 |
| ③ 调用、④ 执行 | 工具、输入坐标系、预测回执、作业 ID，以及动作真正生效的时刻。运行中的场景可以变化。 |
| ⑤ 验证 | 分开回答四问：请求是否受理？执行是否终止？物理效果是否成立？效果是否满足最新意图？“夹空”“已抓稳但放错盘”“看不清落点”应留下不同证据和结论。 |
| ⑥ 下一步 | 根据新证据继续、恢复、询问用户或报告未完成。旧意图下迟到的模型回复要被拒绝。 |

第 2.2 节还要求检验三个跨步骤属性：**多时间尺度**看 S0 是否能在 S2 等待期间继续控制；**持续响应**看用户、身体与场景变化能否及时触发对应路径；**状态持久**看回合内的物体轨迹与跨回合偏好能否按来源更新。用实际时钟和日志验收，论文给出的频率区间只作背景。[论文 §2.2](https://arxiv.org/html/2611.18359v1#S2.SS2) · [本项目时序](architecture.md)

## 第 4 节：怎样获得可比较的证据

**把模型测试和闭环测试分别报告。** 可以给模型同一段相机观测和指令，检查其空间理解与下一步判断；也要让同一模型通过 Harness 真实调用技能，检查机器人最后做成了什么。比较 Harness 时固定模型、动作抽象、构型、观测、任务及预算；比较模型时固定 Harness。原版厨房与新 PiPER 场景可分别用来验证接通，跨构型、跨场景的两个成功率不能直接归因于监控器。要验证监控收益，在同一构型和配对种子上开关监控。[论文 §4.1–4.2](https://arxiv.org/html/2611.18359v1#S4)

| 论文评估维度 | 本轮可记录的证据 |
| --- | --- |
| 知识、理解、推理 | 对固定样本分别检查动作前提、遮挡或目标指代、证据变化后的下一步选择。保留错例。 |
| 工具使用、记忆 | 统计错误参数、过期回执、恢复结果；用换托盘和跨回合物体移位试验检验记忆更新。 |
| 跨构型 | 记录 Steward 与 PiPER 的能力差异。可比任务与动作接口准备好后再做跨构型泛化实验。 |
| 安全 | 测保护响应、停稳证据以及暂停后是否执行了迟到动作。先限定在仿真环境。 |
| 效率、成本 | 分别记决策和任务时延、观测年龄、token、模型调用及资源耗用；减少调用是否损失成功率也需报告。 |

每份回合报告附实验配置卡（Harness Card）。记录模型和预算、Harness 与技能版本、提示与验证条件、构型与控制频率、观测来源和特权信息、推理时仿真时钟是否暂停、种子和样本数、人工或规则介入、终止条件和独立评分。动态测试须证明“推理期间世界确实在演化”，并在同一时间基准上计算从观测采集到动作生效的年龄。按组报告成功数、总数、误报完成、未知结果和置信区间。[论文 §4.2，第 29–31 页](https://arxiv.org/html/2611.18359v1#S4.SS2)

## 第 6 节：本阶段能主张什么

首轮以 **L1 单项技能**（观察、抓稳、验证）和 **L2 完整任务**（在扰动下完成抓放或报告无法完成）为仿真验收目标。开始评测前固定允许的中断、协助、预算和成功条件。L3 跨任务工作流、L4 长期角色、持续自我改进和真实设备可靠性需要后续独立实验。完成一次演示或画出完整架构，都不能给出等级达标结论。[论文图 12，第 44 页](https://arxiv.org/html/2611.18359v1#S6.SS1)
